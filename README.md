# 今天吃什么 🍜

> 解决宇宙难题：今天吃什么。

**在线地址：** https://xtcningran.github.io/what-to-eat/

---

## 功能

- **多人投票**：发起人创建房间，生成 6 位房间码和二维码，同事扫码加入后各自答题，系统综合所有人的偏好推荐餐厅
- **单人模式**：直接答题，跳过等待环节
- **智能评分**：根据口味、预算、用餐速度、菜系偏好、最近去过的餐厅等维度综合打分
- **历史避雷**：自动记录每次选择，近期去过的餐厅在结果页标注并降权
- **黑名单**：发起投票时可排除不想去的餐厅
- **换一批**：结果页可切换最多 3 批候选，每批由随机种子确定，同一房间所有人看到相同结果

## 推荐逻辑

### 1. 汇总权重

每位参与者的答题选项对应一组权重向量（如 `spicy: 1.5`、`budget_max: 60`）。多人投票时：

- 所有维度的权重**累加**（人越多，共同偏好越强）
- `budget_max` 取所有人中的**最小值**（最紧的预算优先）

### 2. 硬过滤

在打分前，先按以下条件缩小候选池：

| 选项 | 过滤逻辑 |
|------|----------|
| 只看供应商 | 保留 `vendor = 1` 的餐厅 |
| 快点吃 | 只保留有 `fast_service` 标签的餐厅 |
| 坐下来好好吃 | 排除有 `no_seat` 标签的餐厅 |
| 越近越好 | 只保留距离办公室 250 米内的餐厅 |
| 黑名单 | 排除本次主持人手动屏蔽的餐厅 |

### 3. 打分

每家餐厅的得分由标签与权重的匹配度决定：

| 餐厅标签 | 对应权重维度 |
|----------|-------------|
| `spicy` | 喜欢辣 |
| `warm_food` | 想喝热汤热食 |
| `meat` | 肉食爱好者 |
| `light_meal` / `healthy` | 清淡健康 |
| `filling` | 吃饱为主 |
| `fast_service` | 快速出餐 |
| `cuisine_chinese/japanese/western/korean` | 菜系偏好 |
| `avg_spend < 25` | 超实惠加分 |
| `rating ≥ 4.5` | 高分好评加分 |
| `noodles` | 避免面食时扣分 |

额外规则：
- 昨天去过：−3.0 分，前两天去过：−1.5 分
- 周一对 `budget_friendly` 餐厅小幅加分；周末对 `premium` 餐厅小幅加分
- 每家餐厅叠加一个随机扰动（`random_bonus × random()`），保证结果有自然变化

### 4. 加权随机抽样

打分后不直接取前 N 名，而是以 `(得分 - 最低分 + 1)` 作为权重进行无放回抽样。高分餐厅被抽到的概率更高，但不保证总是排第一——每次都有机会出现惊喜。

### 5. 确定性多批

为保证同一房间所有人看到相同结果，每批结果用 `房间ID + 批次编号` 作为随机种子生成。换一批不会因客户端不同而出现不同候选。

## 技术栈

- 纯静态 HTML / CSS / JS，托管于 GitHub Pages
- [Supabase](https://supabase.com) 作为后端数据库（房间、答题、历史记录）
- 评分引擎：`docs/js/scoring.js`

## 页面结构

| 文件 | 说明 |
|------|------|
| `index.html` | 首页：发起投票 / 加入房间 / 单人模式 |
| `room.html` | 主持人等待页，显示房间码和答题进度 |
| `join.html` | 加入房间页 |
| `questionnaire.html` | 答题页 |
| `results.html` | 结果展示页 |
| `manage.html` | 餐厅数据管理（内部使用） |
